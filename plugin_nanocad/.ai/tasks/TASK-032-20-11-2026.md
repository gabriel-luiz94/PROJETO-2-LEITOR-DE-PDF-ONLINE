# TASK-032 — Aplicar as regras de Paraíba na leitura do nanoCAD

## Relato

Ao selecionar Paraíba, o plugin não lê o projeto com as regras do OrçaCore. A tela aceita o código 027 mesmo com outro pacote selecionado. Sem download ou cache, a seleção de um projeto sem pacote local podia cair no primeiro pacote do catálogo, geralmente Pernambuco (081).

## Plano

- Resolver as regras pelo código efetivo do projeto antes de ler, incluindo ao digitar 027 e ao retomar uma obra.
- Carregar processamento, classificação, geometria e vínculo de 027 da aplicação em conjunto. Se a aplicação estiver indisponível, usar o cache de 027 ou o seed do leitor que o OrçaCore usa para inicializar Paraíba.
- Mostrar a origem das regras e validar com testes de seleção e compilação para nanoCAD 5 e 26.

## Correção

A tela inicial mantém o código do projeto durante a atualização da lista. A leitura resolve o pacote pelo código, valida o código devolvido pela aplicação e registra a origem das regras. A retomada usa o código gravado na obra. Quando a aplicação está indisponível, o plugin procura o cache do mesmo projeto e avisa se for usar as regras de fábrica do leitor de 027. Esse seed é compartilhado com a aplicação e não inclui um perfil personalizado do desenho ou de vinculação.

## Validação

Passaram 117 testes C# e 54 testes Python do plugin. A cobertura de regressão inclui seleção de 027 com Pernambuco previamente selecionado, cache e seed de 027, rejeição de respostas de outro código e comparação da API do plugin com as regras servidas ao leitor da aplicação. As duas DLLs 0.12.3 e os manifestos foram gerados. O build do 5 usa referências geradas.

## Status

Implementada. Para validar no nanoCAD, conectar ao mesmo OrçaCore usado para ler no aplicativo, selecionar Aplicação: PARAIBA (027), usar Ler projeto e comparar postes, vãos e anotações com o mesmo desenho. Se houver diferença, `ORC_DIAGNOSTICO` registra o perfil e o resultado por anotação.
