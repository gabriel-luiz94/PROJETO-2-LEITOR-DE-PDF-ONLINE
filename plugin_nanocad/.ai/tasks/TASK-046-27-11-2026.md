# TASK-046 · Validar a origem e os conflitos do patch incremental

O patch v1 exige igualdade integral de Model Space, tabelas, blocos e objetos. Uma alteração alheia à operação abortava a sincronização. O diagnóstico v1 agora nomeia `sourceModel` e/ou `sourceDependencies` quando divergem.

## Contrato v2 para o exportador

- Exportar novamente pelo plugin 0.18.4. O campo de raiz `sourceDrawingId` contém o GUID persistente do DWG lido de `$FINGERPRINTGUID`. O exportador web deve copiá-lo para `cadsuitePatch.sourceDrawingId` e informar `cadsuitePatch.version = 2`.
- Manter as listas `added`, `modified`, `deleted` e os registros DXF originais em `before` para cada entidade modificada ou excluída.
- Enviar `references` com um registro DXF original completo por handle distinto de entidade apontada pelas guias novas. Usar lista vazia se o patch não tiver guias novas. Os registros de referência ficam no patch, fora da seção ENTITIES do DXF.
- Preservar na seção TABLES as definições originais de layer, tipo de linha e estilo de texto usados pelas entidades novas e modificadas. O plugin também verifica estilos referenciados por tipos de linha complexos. Mudanças em outras definições e a ordenação dos registros alheios não bloqueiam o patch.
- `sourceModel` e `sourceDependencies` são opcionais no v2. Divergências são registradas no log e a decisão usa a identidade e os conflitos individuais. No v1, as duas assinaturas continuam obrigatórias.

O plugin compara entidades alteradas, excluídas e alvos de guias por handle e conteúdo DXF. Variações de representação numérica são normalizadas. A ordem interna das tags é conservada, em especial para vértices e XDATA. Uma mudança semântica ou um alvo ausente bloqueia a operação. As restrições experimentais, a confirmação e o backup da TASK-045 continuam valendo.

Os testes cobrem mudanças alheias ao patch, outro DWG, alvo modificado, referência ausente e dependência usada divergente. O fluxo nativo com o exportador web ainda depende de validação no nanoCAD.
