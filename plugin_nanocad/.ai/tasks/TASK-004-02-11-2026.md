# TASK-004 — Diagnóstico com desenho real

## Objetivo
Ver exatamente o que o plugin enxerga num DWG e transformar desenhos reais em teste, sem depender de reproduzir o problema no CAD.

## Origem
Relato do usuário (02/11): "as regras leram todo o texto mas não filtraram", "não identificou os blocos pelas linhas guias", "seleção manual não carrega nada".

## O que foi feito
- O DWG passa a ser lido como **desenho bruto** (`Nucleo/DesenhoBruto.cs`): texto original, cor sem resolver, MLEADER, contorno.
  A interpretação saiu do CAD para o núcleo (`MontadorDesenho`), que é a mesma para o nanoCAD, os testes e o diagnóstico.
- `ORC_DIAGNOSTICO` grava `<desenho>.diagnostico.json`: resumo (entidades por tipo/layer, blocos, redes MT/BT, guias,
  postes, avisos do que faltou), cada texto com o resultado das regras e o DESTINO (poste, vão, avulso, ignorado + motivo)
  e o desenho bruto inteiro. Também abre uma tabela com isso no nanoCAD.
- Log em `%APPDATA%\OrcamentoNanoCAD\log.txt` (comandos, mensagens, erros com detalhes).
- `tests/oraculo/dxf_para_bruto.py`: DXF → desenho bruto (e, com `--app`, o que o Leitor da APLICAÇÃO faz com o mesmo DXF).
  `gerar_dxf_teste.py` monta um DXF de teste no padrão de Pernambuco (TEXT/MTEXT com cores, LEADER, MLEADER, blocos com atributo).
- Testes: `LeitorDxfTests` — paridade texto a texto com o Leitor da aplicação, leitura completa, e todo JSON em
  `referencias/desenhos/` (diagnóstico ou bruto) é lido nos testes.
