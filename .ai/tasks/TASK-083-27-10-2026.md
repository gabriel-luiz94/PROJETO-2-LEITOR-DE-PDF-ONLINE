## Objetivo
Hoje a linha de Cabos é `ATIVO FASE COMPRIMENTO` (`C16 3 45`). A tabela passa a aceitar também a notação do LABEL, como Outros aceita dois formatos (TASK-081): o usuário vê o que digitou e a tradução para o formato antigo é implícita no cálculo, no vínculo e na validação.

## Gramática proposta
`[Nx]CODIGO[(neutro)][-TENSÃOkV] COMPRIMENTO`
- `Nx`/`NX` = fases (padrão 1x). Tensão (`-13,8kV`, `+20kV`) é ignorada.
- Neutro: `(7,94)` → `CAZ7,94` qtd 1; `(16)`/igual à seção → mesmo cabo, qtd 1; `(S04)`/`[C16]` soltos = cabo de neutro próprio.
- Exemplos: `3xA35P(7,94)-13,8kV 45` → `A35P 3 45` + `CAZ7,94 1 45`; `3xC16(16) 30` → `C16 3 30` + `C16 1 30`; `1xS1/0-7,9kV 20` → `S1/0 1 20`.

## A fazer (mesmo desenho da TASK-081)
Módulo único Python + JS com paridade (`anotacao_cabos`), usado por: cálculo (`extrair_ativo_cabo`), Totalizadora (`syncTotalizadora` + espelho autônomo), validação camada 1, vínculo cabo↔estrutura, contadores de rede (`extrairPrefixoEComprimentoCabo`), ajustes (não editam). Uma linha não mistura os dois formatos; a célula nunca é reescrita.

## Decisões do usuário (2ª rodada)
- Neutro entra na soma de comprimento da rede. `RAMA25`/`PB35`/`PB70`/`PB120` = `1x`+código; `16` = `C16`; `3xW2,25` → ativo `W2,25`; cabo que começa com `C` = um único código sem espaços (`C 3x1x95(95)` → `C3x1x95(95)`?, `1x` inicial = fases). Comprimento `45 m`/`45m`/`45M` (mesma linha ou abaixo; o Leitor junta): `3x[ATIVO](NEUTRO) [COMPRIMENTO] m`.
