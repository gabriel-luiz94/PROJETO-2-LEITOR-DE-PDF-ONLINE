# TASK-038-05-10-2026

**`adicionar_ativo` aceita quantidade negativa (prefixo `*`, linha viva/retirada)**

## Objetivo

Permitir que a ação `adicionar_ativo` (motor de ajustes, TASK-022) adicione um ativo com quantidade **negativa**, gerando o prefixo `*` (ex.: `*1-PR`) em vez de rejeitar ou produzir um texto que o cálculo não leria como negativo.

## Contexto

Usuário pediu um ajuste: "se existir TR110 (trafo mono) na linha, adicionar 1-PR15 2-P50 1-PR127 *1-PR 3-EST35". Quatro dos cinco ativos são diretos (`adicionar_ativo` com `qtd` positivo, uma ação por ativo, mesma condição `{"tem": "TR110"}`). O quinto (`*1-PR`) pedia quantidade negativa — e a ação não suportava isso: `services/ajustes_planilhas.py:191` exigia `qtd > 0`, rejeitando qualquer negativo na validação de schema.

Confirmado que o formato `*<n>-<ativo>` é a única forma válida de representar quantidade negativa em Outros (`services/orcamento_calc.py:tokenizar_outros` faz `"-" → " "` e depois `"*" → "-"`, nessa ordem — um `-` literal na posição de quantidade se perde, só `*` é lido como sinal).

## Situação atual (antes desta tarefa)

- `validar_acoes`: `"qtd" in a and not (_numero_ok(a["qtd"]) and a["qtd"] > 0)` — rejeitava qualquer `qtd <= 0`.
- `_t_adicionar_ativo` usava `_n(qtd)` (de `services/regras_dominio.py`, só formata o número) para montar o token — com `qtd` negativo produziria `-1-PR`, que o tokenizador de Outros não lê como negativo (perde o sinal).
- `_num(qtd)` (privado deste módulo) só reconhecia dígitos puros — não parseava um token **já existente** como `*1-PR` de volta para `-1.0`, quebrando o modo `se_ja_existe: "somar"` quando o ativo já estava lá com quantidade negativa.

## Comportamento desejado

- `qtd` pode ser qualquer número **diferente de zero** (positivo ou negativo). Zero continua rejeitado (não faz sentido "adicionar zero").
- `qtd` negativo gera o token com prefixo `*` (ex.: `qtd: -1` → `*1-PR`), nunca com `-` literal.
- `se_ja_existe: "somar"` soma corretamente mesmo quando o token já existente é negativo (`*1-PR`) ou quando a soma muda de sinal (ex.: `5-PR` + `qtd: -2` → `3-PR`, sem `*`, porque o resultado é positivo).
- `se_ja_existe: "substituir"` com `qtd` negativo também gera o prefixo `*`.

## Restrições

- [x] Formato de ativo `<qtd>-<ativo>` (OUTROS) — a mudança é sobre como esse formato é **gerado**, não sobre o formato em si; o prefixo `*` já é parte do formato existente (linha viva), só não era alcançável por esta ação.
- [x] Nenhum dos demais contratos listados em `RULES.md` (Regra 5).
- Só o módulo `services/ajustes_planilhas.py` foi tocado — `_num`/`_juntar`/`_RE_NUM` são privados deste arquivo (não importados de `regras_dominio.py`), então a correção não tem efeito em nenhum outro módulo (validação de regras de domínio, Totalizadora, modo autônomo etc.).

## Critérios de aceite

- [x] `validar_acoes` aceita `qtd` negativo e continua rejeitando `qtd == 0`.
- [x] `adicionar_ativo` com `qtd: -1` numa linha sem o ativo gera `*1-<ativo>`.
- [x] `se_ja_existe: "somar"` com token existente negativo soma corretamente (`*1-PR` + `qtd: -2` → `*3-PR`).
- [x] `se_ja_existe: "somar"` que troca de sinal não deixa `*` residual (`5-PR` + `qtd: -2` → `3-PR`).
- [x] `se_ja_existe: "substituir"` com `qtd` negativo gera `*`.
- [x] O exemplo completo do usuário (5 ações, mesma condição `{"tem": "TR110"}`) produz exatamente `1-TR110 1-PR15 2-P50 1-PR127 *1-PR 3-EST35`, confirmado rodando o motor real.
- [x] Documentação `.ai` atualizada conforme `RULES.md` Regra 9
- [x] `STATE.md` atualizado conforme `RULES.md` Regra 10

## Riscos

Limitação conhecida, fora do escopo desta tarefa: `mesclar_duplicadas` (`_t_mesclar`) tem a mesma classe de problema ao somar tokens repetidos — se dois tokens do mesmo ativo já existentes forem negativos, o resultado pode sair com `-` literal em vez de `*`. Não foi tocado porque não fazia parte do pedido original; registrar depois se for incomodar na prática.
