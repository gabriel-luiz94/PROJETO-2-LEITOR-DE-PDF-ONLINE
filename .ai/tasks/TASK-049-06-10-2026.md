# TASK-049-06-10-2026

**`adicionar_ativo`: item da lista pode ter fator próprio sobre a quantidade dinâmica compartilhada**

> Usuário tentou usar a sintaxe `código:qtd` da TASK-048 (`90277:-1, 90279:1`) junto com "mesma
> quantidade de outro ativo" (U4, fator 2), esperando "duas vezes a quantidade de U4, um código
> negativo e outro positivo". O resultado não aplicou a quantidade dinâmica — cada item usou
> literalmente -1/1, porque `qtd` própria SUBSTITUI a compartilhada (comportamento correto da
> TASK-048, mas não o que o usuário queria aqui). Perguntado "não podemos adicionar a lógica do
> fator?" — confirmado, implementada em 2026-10-06.

## Objetivo

Permitir que um item da lista de `adicionar_ativo.ativo` tenha seu PRÓPRIO `fator`, que MULTIPLICA
a mesma base da quantidade compartilhada (a mesma soma, se `qtd` for dinâmico) em vez de substituí-la
por um valor fixo — diferente de `qtd` própria (TASK-048), que é um valor literal independente da
base compartilhada.

## Contexto

A TASK-048 deu a um item da lista uma quantidade própria LITERAL (`{"ativo": código, "qtd": N}`),
que ignora completamente a `qtd` compartilhada da ação. Isso não serve quando o usuário quer que
cada código continue dependendo da MESMA quantidade dinâmica (ex.: soma de outro ativo da linha),
só com um multiplicador/sinal diferente por código — caso real: "duas vezes a quantidade de U4, um
ativo negativo, outro positivo".

## Situação atual (antes desta tarefa)

- Item da lista só podia ser string (usa a `qtd` compartilhada) ou `{"ativo": código, "qtd": N}`
  (substitui a compartilhada por um valor literal fixo, TASK-048) — nenhum dos dois permitia manter
  a dependência da quantidade dinâmica com um multiplicador próprio.

## Comportamento desejado

1. Um item da lista pode ser `{"ativo": código, "fator"?: número}` — MULTIPLICA a base (não
   escalada) da `qtd` compartilhada: a soma de `qtd.soma`, se `qtd` for dinâmico, ou o próprio
   número, se `qtd` for literal. Substitui só o FATOR, mantendo a base compartilhada.
2. `"qtd"` e `"fator"` no mesmo item são mutuamente exclusivos — item só pode ter um dos dois (ou
   nenhum, usando a `qtd` compartilhada por completo, como na TASK-047/048).
3. Itens string e itens com `qtd` própria continuam funcionando exatamente como antes (TASK-047/048,
   sem alteração).
4. `descrever_acao()` descreve o fator próprio em português.
5. UI: o mesmo campo "códigos" ganha a sintaxe `código:xN` (ex.: `90277:x-2`) para fator próprio,
   distinta de `código:qtd` (valor fixo) — sem campo/seletor novo.
6. Exemplo exato do pedido do usuário: `{"acao": "adicionar_ativo", "tabela": "outros", "ativo":
   [{"ativo": "90277", "fator": -2}, {"ativo": "90279", "fator": 2}], "qtd": {"soma": "U4"},
   "quando": {"tem": "U4"}}` — com `2-U4` na linha, gera `*4-90277` e `4-90279`.

## Restrições

- [x] Nenhum dos contratos listados em `RULES.md` (Regra 5) muda.
- `adicionar_ativo` continua restrito a Outros (`SO_OUTROS`).
- `"qtd"` e `"fator"` não podem coexistir no mesmo item (ambíguo — rejeitado na validação).

## Critérios de aceite

- [x] `{"ativo": "90277", "fator": -2}` com `qtd: {"soma": "U4"}` numa linha com `2-U4` adiciona
  `*4-90277`.
- [x] `fator` próprio também funciona quando `qtd` compartilhada é um número literal (multiplica o
  próprio número).
- [x] Lista mista: item com `fator`, item com `qtd` própria e item string, todos na mesma lista,
  cada um resolvido de forma independente.
- [x] Base compartilhada zero (seletor da soma não casou) não adiciona o item de `fator`.
- [x] Validação rejeita item com `qtd` E `fator` juntos, `fator` não numérico.
- [x] `descrever_acao()` gera frase em português correta para item com fator próprio (base dinâmica
  e base literal).
- [x] UI: sintaxe `código:xN` no campo "códigos" produz o JSON esperado (confirmado via Playwright).
- [x] Documentação `.ai` atualizada conforme `RULES.md` Regra 9.
- [x] `STATE.md` atualizado conforme `RULES.md` Regra 10.
