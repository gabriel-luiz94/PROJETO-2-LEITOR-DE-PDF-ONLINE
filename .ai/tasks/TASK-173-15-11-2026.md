# TASK-173 — Dicionário de cabos por projeto (notação, nível, seção e ordem do "maior")

**Status:** CONCLUÍDA (15/11/2026) — ADR-007

## Objetivo

Tirar do código as convenções de nome de cabo de Pernambuco e pôr num **dicionário de cabos** editável por projeto. A notação da
tabela Cabos, o nível MT/BT, a seção usada no "maior primeiro" e a ordem do "maior" passam a vir dele; sem dicionário, tudo funciona
como hoje.

## Contexto

- Notação do LABEL: TASK-083 (`services/anotacao_cabos.py` + `static/anotacao_cabos.js`, paridade em `tests/test_anotacao_cabos.py`).
- Nível e fases: TASK-092 (`derivar_cabo`/`extra_cabo`, `services/vinculacao_regras.py:170-192` + JS:53-59).
- Seção e "maior primeiro": TASK-169 (`secao_cabo`, `vinculacao_regras.py:523-537`); `ordem_maior` da config (padrão `C,P,A`, linha 18).
- Tabela de Cabos da vinculação (TASK-084): regex por família + `valor_cabo`. O dicionário não a substitui: ela continua dizendo
  **em quais estruturas** o cabo entra; o dicionário diz **o que o cabo é**.

## Situação atual (fixo no código)

1. `_RE_CODIGO`, `_RE_CURTO` (`RAMA|PB`), `_RE_NUMERO_SOZINHO` (`16` → `C16`), neutro `(7,94)` → `CAZ7,94`, `_RE_POTENCIA` (`C 3x1x95`).
2. Nível = `MT` se o texto tem `NkV` com N > 1; senão `BT` (cabo digitado sem tensão vira BT).
3. Seção = número do código; AWG por tabela (`S04` = 21,2; `S1/0` = 53,5). `A185P` = 185, `PB35` = 35.
4. `ORDEM_MAIOR_PADRAO = ["C","P","A"]`; em PE o valor do protegido é `X`.

## Comportamento desejado

### A. Dicionário (por projeto)

Lista de linhas, a primeira que casa vence:

| Campo | Exemplo | Uso |
|---|---|---|
| `padrao` | `^A(\d+)P$` | casa o código do cabo principal (sem `Nx`, neutro e tensão) |
| `familia` | `PROTEGIDO` | rótulo livre (relatórios, tela) |
| `valor_cabo` | `X` | valor do `tipocabo`; substitui o `valor_cabo` da Tabela de Cabos quando esta estiver vazio |
| `secao` | `$1` ou número | seção em mm² (`$1` = grupo da regex); AWG por tabela opcional `{"4":21.2,"1/0":53.5}` |
| `nivel` | `MT` / `BT` / vazio | nível quando o texto não traz tensão |
| `fases_padrao` | `1` | fases quando o texto não traz `Nx` |
| `apelidos` | `["16"]` → `C16` | textos curtos que viram o código (substitui `RAMA|PB` e o número sozinho) |
| `neutro` | `CAZ{valor}` | como montar o neutro do parêntese com vírgula |

Mais um campo do projeto: `ordem_maior` (lista de `valor_cabo`), já existente, passa a ter o padrão vindo do dicionário.

### B. Uso

1. `anotacao_cabos.interpretar` consulta apelidos e neutro do dicionário; sem dicionário, as regras atuais.
2. `derivar_cabo`: tensão no texto continua mandando; sem tensão, usa `nivel` do dicionário (hoje: BT).
3. `secao_cabo`: dicionário primeiro; sem linha, a regra atual.
4. Paridade Python = JS em tudo que a tela usa.

### C. Tela

Aba "Dicionário de cabos" no modal Vinculação (mesmo editor de tabela da Tabela de Cabos), com "Testar um texto"
(`3xA35P(7,94)-13,8kV 45 m` → código, fases, neutro, nível, seção, valor_cabo, linha do dicionário usada).

### D. Pernambuco

Gerar `data/pacotes/081/dicionario_cabos.json` com o comportamento atual (C, A…P, S/W, PB, RAMA, CAZ) — é o mesmo resultado dos
testes atuais quando carregado.

## Restrições

- Projeto sem dicionário: idêntico ao de hoje (todos os testes de `anotacao_cabos`, vinculação e Totalizadora passam).
- Contratos: formato de ativo CABOS **não muda** (o dicionário só interpreta); configuração de vinculação ganha campo opcional.
