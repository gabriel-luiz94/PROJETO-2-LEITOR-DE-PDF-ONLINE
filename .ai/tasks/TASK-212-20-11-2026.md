# TASK-212 — Paridade da leitura DXF com o nanoCAD

O Excel da nota mostrou 74 cabos no Leitor e 42 no plugin. O porte C# ignora a seleção espacial de metragem e pode classificar estruturas e placas como cabos. A prioridade é executar a mesma extração e o mesmo motor antes de associar geometria ou vínculos.

## Plano

A API autenticada lê o DXF com o extrator da aplicação e classifica com o JavaScript do Leitor. O plugin associa o resultado com a geometria do desenho ativo. O teste compara os resultados da API e do Leitor com os mesmos dados e projeto. Os builds do nanoCAD 5 e 26 usam a mesma integração.

## Validação

Passaram 79 testes Python do plugin e do Leitor, incluindo a comparação do mesmo DXF gerado em teste pela API do plugin e pelo caminho de extração e processamento do Resumo. O teste verifica a estrutura CE2 sem metragem, uma placa fora de Cabos e um cabo com o comprimento correto, apesar de um comprimento distante aparecer antes na lista. A execução no Windows com a nota do usuário segue pendente.

O extrator, o arquivo JavaScript do motor, as regras e a rota do Leitor permanecem com a calibração existente. A rota nova só atende o plugin autenticado.
