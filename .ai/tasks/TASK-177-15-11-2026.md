# TASK-177 — Pacote de projeto: exportar e importar tudo de um projeto num arquivo (e fim dos `if "081"`)

**Status:** CONCLUÍDA (15/11/2026) — ADR-007. Depende de TASK-173 a TASK-176 para os itens novos; pode começar com o que já existe.

## Objetivo

Quem distribui o programa manda **um arquivo** com tudo o que um projeto precisa; quem recebe importa num projeto vazio e começa a
orçar. Pernambuco (081) passa a ser o primeiro pacote, e o código deixa de ter casos especiais para ele.

## Contexto (o que hoje é por projeto, espalhado)

| Item | Onde vive hoje |
|---|---|
| Base técnica | CSV importado no admin (coluna PROJETO), `data/tabela_seed.csv` (RONDONIA) |
| Vinculação (cabos, estruturas, `ordem_maior`, scripts) | tabela `vinculacao_config` (SQLite + Supabase); semente `data/vinculacao_pernambuco_seed.json` só para 081 (`routers/vinculacao_config.py:22-72`) |
| Regras do leitor (classificação/processamento) | por projeto; sementes PE em `data/regras_leitor_*_pernambuco_seed.json` (`routers/regras_leitor.py:171-231`) |
| Contextos e Ajustes | TASK-044 / ADR-006 |
| Tabela regional (`OBRA.REGIAO`) | `services/obra_params.py:16` `_TABELAS = {"PERNAMBUCO": …}` |
| Modelos de obra | TASK-058/060 |
| Novos: dicionário de cabos, postes, desenho, exportação, casos de referência | TASK-173 a 176, 178 |

## Comportamento desejado

1. **Formato:** `.zip` com `manifest.json` (`formato: "pacote-projeto"`, `versao_formato`, `versao_programa`, `projeto`, `descricao`,
   lista de partes e hash de cada uma) + um arquivo por parte (`base.csv`, `vinculacao.json`, `leitor_classificacao.json`, …).
   Partes ausentes = "não mexer".
2. **Exportar:** menu do projeto → "Exportar pacote" (marca quais partes vão).
3. **Importar:** num projeto (novo ou existente) com pré-visualização por parte: "novo / substitui / igual", contagens, avisos do
   validador da base e de `validar_config`; nada é gravado antes de confirmar. Importação de pacote de versão de formato mais antiga
   passa por migração; mais nova que o programa → recusa com mensagem clara.
4. **Pontos de partida:** `data/pacotes/081/` (as sementes atuais de PE) e `data/pacotes/rondonia/` (`tabela_seed.csv`). Um projeto
   sem configuração usa o pacote marcado como ponto de partida **do próprio projeto** (campo no cadastro do projeto), não um `if`.
   Somem `PROJETO_PERNAMBUCO`, `_seed_pernambuco`, `_atualizar_seed_pernambuco` e `_TABELAS` fixos.
5. **Isolamento:** importar num projeto não altera outro (testes com dois projetos).

## Restrições

- Projeto 081 sem configuração salva continua nascendo igual a hoje (agora pelo pacote).
- Colunas do CSV da base não mudam. Schema do Supabase: campo novo no cadastro do projeto (`pacote_inicial`) — marcar no RULES.
- Contratos tocados: [x] Schema do Supabase (campo opcional); demais não.

## Critérios de aceite

- [x] Exportar o 081 e importar num projeto vazio "teste": orçamento de uma obra de exemplo igual nos dois projetos.
- [x] Pré-visualização mostra o que muda por parte; cancelar não grava nada.
- [x] `grep -r "081\|PERNAMBUCO" services routers` sem casos especiais (só dados em `data/pacotes/`).
- [x] Pacote com `versao_formato` maior que a suportada é recusado com mensagem.
