# TASK-043-06-10-2026

**Suporte a arquivos .dwg via conversão online (CloudConvert) antes da extração**

> Pedido do usuário: "conseguiria ler um arquivo .dwg?" → confirmado que não (formato binário
> proprietário, `ezdxf` só lê `.dxf`) → usuário pediu para o próprio programa converter
> internamente, usando uma ferramenta online. Implementada em 2026-10-06.

## Objetivo

Permitir que o usuário envie um `.dwg` (Leitor manual e modo autônomo) e o programa converta para
`.dxf` automaticamente via uma API de conversão na nuvem, antes de seguir pelo mesmo caminho de
extração que já existe para `.dxf` nativo. `.dxf`/`.pdf` continuam 100% offline, sem nenhuma
chamada nova.

## Contexto

`.dwg` é o formato binário proprietário da Autodesk; `ezdxf` (usado em `services/dxf_service.py`)
só lê `.dxf`. Não existe biblioteca Python livre e madura para `.dwg` nativo. Opções levantadas:
ODA File Converter (executável local, não é lib Python, complicado de empacotar/rodar headless no
servidor) vs. uma API de conversão na nuvem. Decisão do usuário: API na nuvem.

Duas decisões confirmadas com o usuário antes de implementar:
1. **Serviço**: CloudConvert (API v2, autenticação simples por API key, suporte direto a DWG→DXF,
   free tier). Alternativa descartada: Autodesk Platform Services (OAuth2 mais complexo).
2. **Credencial**: mesmo padrão já usado para a chave do Gemini (`routers/ai_chat.py`) — variável
   de ambiente como padrão do sistema + o usuário pode digitar a própria chave, que é salva no
   servidor (`configuracoes`) só depois de confirmada por um uso com sucesso. Precedência:
   usuário (header) > salva > padrão do ambiente.

Isso significa que, pela primeira vez neste projeto, uma funcionalidade de **leitura de arquivo**
(não só IA/sync) passa a depender de internet — aceito como exceção pontual, igual ao chat de IA e
à sincronização com Supabase: só quando o arquivo é `.dwg`.

## Situação atual (antes desta tarefa)

- `routers/upload.py` (`POST /upload`, `GET /extract-local`) e `services/autonomo/pipeline.py`
  (`ler_arquivo`, pasta monitorada) só reconheciam `.dxf`/`.pdf`.
- `static/index.html`/`script.js` (tela Leitor) recusavam qualquer outra extensão no upload.

## Comportamento desejado

1. Novo `services/cloudconvert_service.py`: função com I/O real (`converter_dwg_para_dxf`) que
   cria um job no CloudConvert (import/upload → convert dwg→dxf → export/url), envia o arquivo,
   espera (polling) terminar, baixa o `.dxf` resultante. Levanta `ErroConversaoDwg` com mensagem
   seção para o usuário em qualquer falha (sem chave, rede, cota, arquivo inválido, timeout).
2. `routers/upload.py`: resolve a credencial (header `X-CloudConvert-Key` > `configuracoes` >
   `CLOUDCONVERT_API_KEY` do ambiente), converte `.dwg` → `.dxf` e segue pelo mesmo caminho de
   extração do `.dxf` nativo, nos dois endpoints (`/upload`, `/extract-local`). Chave do usuário só
   é persistida depois que uma conversão com ela der certo.
3. `services/autonomo/pipeline.py`: `EXTENSOES` ganha `.dwg`; `ler_arquivo` converte antes de
   extrair, usando só a credencial salva/padrão (sem header possível em processamento de pasta em
   segundo plano).
4. `static/index.html`/`script.js`: aceita `.dwg` no input de arquivo e na validação client-side;
   novo botão "Chave DWG" + modal para o usuário configurar sua própria chave do CloudConvert
   (mesmo padrão visual dos outros modais da página, persistida em `localStorage`, enviada como
   header `X-CloudConvert-Key` nas chamadas a `/upload`/`/extract-local`).
5. `routers/health.py`: novo campo `cloudconvert_key_source` (`salva`/`padrao`/`nenhuma`, nunca o
   valor), mesmo padrão de `ai_key_source`, usado pelo texto de status do modal.

## Riscos

- Dependência de um serviço externo pago (CloudConvert): free tier tem limite diário; se esgotado,
  o usuário recebe o erro do CloudConvert (`ErroConversaoDwg`) de forma clara, sem crash.
- Conversão de arquivos CAD grandes pode levar mais que o timeout de 90s configurado
  (`TIMEOUT_SEGUNDOS` em `cloudconvert_service.py`) — ajustável se aparecer na prática.
- No modo autônomo (pasta monitorada), sem header possível: se nenhuma chave salva/padrão estiver
  configurada, todo `.dwg` na pasta vai para `erros/` com a mensagem clara do CloudConvert — é o
  comportamento esperado, não um bug.
