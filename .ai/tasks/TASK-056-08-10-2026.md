# TASK-056-08-10-2026

**Exportar e importar obras salvas (arquivo `.obra.json`)**

## Objetivo

Permitir que uma obra salva seja **exportada para um arquivo** e **importada por qualquer usuário**, que a recebe como uma **cópia particular dele**. É a base das TASK-057 (obras públicas) e TASK-058 (modelos).

## Contexto

Pedido do usuário (2026-10-08): "as obras salvas podem ser exportadas e importadas por outros usuários?". Hoje cada obra é só do usuário que a salvou (todas as rotas de `routers/obras.py` filtram por `user_id`) e **não existe** exportar/importar. Esta é a primeira de três tarefas pedidas em sequência: **056** (esta), **057** (públicas/particulares), **058** (modelos).

## Situação atual

- `routers/obras.py`: `GET /api/obras`, `/indice`, `/{id}`, `POST`, `DELETE`; tabela `obras(id, nome, data, dados_json, user_id, projeto)`.
- `dados_json` = `JSON.stringify(tableStates)` do Resumo (`static/resumo.js`, botão Salvar obra): `{cabos:{bodyId,data}, outros:{...}, totalizadora:{...}, regras:{...}}`. O restaurador (`restoreObraSnapshot`) aceita também `{cabos:[...], outros:[...]}`.
- Obras do modo autônomo carregam `autonomo:{execucao_id,...}` dentro do `dados_json`.
- Modal **Carregar Obra** (`static/resumo.html`, `#modal-load-obra`; lista em `resumo.js` `btn-load-obra`) já oferece Carregar / Adicionar / Subtrair / Excluir por obra.

## Comportamento desejado

1. **Exportar** (botão em cada obra da lista): baixa `<nome>.obra.json`:
   ```json
   {"formato": "leitor-obra", "versao": 1, "exportado_em": "...", "tipo": "obra", "nome": "...", "projeto": "229",
    "dados": {"cabos": [{"entidade","operacao","ativo","qtdAtivos"?}], "outros": [...], "totalizadora": [...]}}
   ```
   Só os dados da obra: **sem** `regras` de conversão (são do projeto), **sem** marcas internas (`autonomo`, ids, usuário, e-mail).
2. **Importar** (botão **Importar obra** no modal): escolhe o arquivo → o programa **valida** e cria uma obra **nova** (id novo `obra_<timestamp>`), **particular**, do usuário que importou, com o nome do arquivo (+ " (importada)" se já existir um igual).
3. **Qualquer usuário** (operador ou admin) pode importar (decisão do usuário). Nada do arquivo original é alterado; importar nunca sobrescreve uma obra existente.
4. **Projeto da obra:** só se importa obra do **mesmo projeto selecionado na tela**; se o `projeto` do arquivo for outro, a importação é recusada com mensagem clara ("esta obra é do projeto X; o projeto selecionado é Y"). Nada é criado.
5. **Validação do arquivo** (no servidor): tamanho ≤ 5 MB; `formato` e `versao` conhecidos; `dados.cabos`/`outros` listas de objetos com `entidade`/`operacao`/`ativo` em texto, até 5.000 linhas cada; campos desconhecidos descartados; erros listados em português por linha.
6. Conteúdo do arquivo entra na tela só por `textContent` (nada de HTML); o arquivo não executa nada.

## Restrições

- Sem alteração de schema (usa a tabela `obras` como está).
- Não mudar o formato do `dados_json` das obras já salvas; o importador **normaliza** as formas antigas (`cabos` como lista ou como `{data:[...]}`).
- Respeitar a isolação de testes (`tests/conftest.py`): nuvem só com cliente falso.
- Contratos (RULES Regra 5) tocados:
  - [x] `localStorage['processar_dados']` · [ ] `orcamentoPayload` · [ ] payload de `POST /api/orcamento/calcular`
  - [x] Formato de ativo `[ATIVO] [FASE] [COMPRIMENTO]` / `<qtd>-<ativo>` (só validado, não alterado)
  - [x] Schema do Supabase — **não** nesta tarefa

## Critérios de aceite

- [x] `GET /api/obras/{id}/exportar` devolve o arquivo (só obra própria nesta tarefa) com `Content-Disposition`
- [x] `POST /api/obras/importar` valida e cria cópia particular do usuário que importa, com id novo
- [x] Round-trip: exportar → importar → as tabelas carregadas são idênticas às originais (Cabos, Outros e Totalizadora)
- [x] Recusa arquivo inválido, grande ou de **outro projeto que não o selecionado** com mensagem clara; nada é gravado nesses casos
- [x] Botões **Exportar** e **Importar obra** no modal Carregar Obra; verificado no Chromium com **dois usuários** (um exporta, o outro importa)
- [x] Documentação `.ai` (STATE, CHANGELOG, ARCHITECTURE) e manual atualizados

## Exemplos

Usuária A exporta "Rede Norte" → `Rede_Norte.obra.json`; usuário B (operador, mesmo projeto) clica **Importar obra**, escolhe o arquivo e vê "Rede Norte (importada)" na **sua** lista, particular. A obra de A continua só de A.

## Arquivos potencialmente afetados

`routers/obras.py` (rotas `exportar`/`importar`), novo `services/obras_arquivo.py` (formato, normalização e validação puras), `static/resumo.js` e `static/resumo.html` (botões e leitura do arquivo), `tests/test_obras_arquivo.py`, `.ai/*`, `data/manual_regras_e_ajustes.md` (ou novo trecho do manual).

## Riscos

- Arquivo malicioso/enorme → limites de tamanho/linhas/profundidade e validação estrita.
- Obras antigas com formatos diferentes → normalizador testado com os formatos reais (`tableStates` completo e `{cabos:[...]}`).
- Rota `/api/obras/importar` colide com `/{obra_id}`: registrar a rota estática **antes**.

## Plano de teste

pytest: formato (ida e volta), normalização, limites, rejeições, id novo, particularidade (obra de A nunca aparece para B), projeto inexistente, nuvem com cliente falso. Chromium: dois tokens, exportar/importar, arquivo inválido.

## Decisões do usuário (2026-10-08)

- Importar: **qualquer usuário**.
- Obras importadas viram **particulares do importador**.

## Decisões confirmadas (2026-10-08)

1. A **Totalizadora vai no arquivo**: sim.
2. **Limite de 5 MB** por arquivo: sim.
3. **Importar só obra do mesmo projeto do projeto selecionado na tela**: a importação é recusada se o `projeto` do arquivo for diferente do projeto selecionado (em vez de oferecer outro projeto). Isso substitui o item 4 do comportamento desejado.
