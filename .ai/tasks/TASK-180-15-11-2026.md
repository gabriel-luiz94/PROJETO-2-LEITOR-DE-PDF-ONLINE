# TASK-180 — "Montar Orçamento" sempre recalcula; resultado gravado só volta ao abrir um .obra na tela do Resultado

**Status:** PLANEJAMENTO (15/11/2026)

## Objetivo

Clicar em **Montar Orçamento** sempre recalcula o Resultado com a tabela de orçamento atual. O resultado gravado no projeto só é
recuperado quando o usuário já está na tela do Resultado e abre um arquivo `.obra` ali.

## Contexto

- TASK-154: o projeto (`.obra`) grava o Resultado (`projeto_trabalho.resultado = {assinatura, linhas}`), inclusive as edições manuais.
- A assinatura é o hash do payload (`orcamentoPayload`), sem nada da base. Trocar a base não muda a assinatura.

## Situação atual

- `static/resultado_orcamento.html:1433-1445` (`montarOrcamento`): com projeto aberto, chama `GridRProjeto.carregarResultado(hash do payload)`.
  Se o projeto tem resultado com a mesma assinatura, **restaura as linhas gravadas e não chama `/api/orcamento/calcular`**
  (log "Resultado restaurado do projeto: N item(ns)").
- `static/projeto.js:720-728` (`carregarResultado`): procura primeiro o resultado pendente em memória, depois o do arquivo.
- O resultado sai velho se o usuário importa uma base nova e monta o mesmo Resumo. Exemplo real de 15/11: base nova com o jumper do RL
  em XLPE 185 (2212025). O Simulador da ficha mostra o 185, mas Montar Orçamento continua trazendo o XLPE 35 (2212015) gravado antes.
- `ativarAberto` / `abrirDoPlugin` (`static/projeto.js:438-490`) carregam o Resumo do `.obra`, mas a tela do Resultado aberta não muda:
  continua mostrando o que estava nela.

## Comportamento desejado

1. **Montar Orçamento** (`resumo.js:4878` → Resultado): o Resultado chama sempre `/api/orcamento/calcular` com o payload e a base atual.
   Não consulta `carregarResultado`, nem o pendente em memória nem o do arquivo.
   - Com projeto aberto, o resultado recalculado passa a ser o resultado do projeto, como já acontece depois de um cálculo:
     `acompanharResultado` grava com o salvamento automático ligado; desligado, fica pendente até o Salvar. O resultado anterior é
     substituído.
   - Se o resultado substituído tinha edições manuais, o log avisa: "Recalculado com a base atual; as edições manuais do resultado
     anterior foram substituídas." Não há pergunta, e o cálculo não é bloqueado.
2. **Abrir `.obra` com a tela do Resultado à vista** (menu Projeto → Abrir, ou o projeto entregue pelo plugin do nanoCAD, TASK-163):
   - O `.obra` tem resultado gravado: o Resultado mostra essas linhas, inclusive as edições, **sem recalcular**. Log: "Resultado do
     projeto 'X' (gravado no arquivo)". A partir daí a tela acompanha o projeto (`acompanharResultado`).
   - O `.obra` não tem resultado: a tabela é esvaziada (não fica o resultado de outro projeto) e mostra "Este projeto não tem resultado
     gravado. Volte ao Resumo e clique em Montar Orçamento."
   - Opções Mesclar/Sobrescrever do Abrir: mantêm a tabela atual do Resultado, porque a tela vale. Só **Abrir** troca.
3. **Qualquer outra entrada no Resultado** (recarregar a página, voltar ao Resultado pelo menu, abrir um projeto estando em outra tela
   e depois ir ao Resultado): recalcula com o último payload, como no item 1. Nunca restaura sozinho.
4. Sem mudança: `?rec=` (RECs do banco), "Comparar com… .obra" (TASK-157) e o "Salvar como", que leva o resultado atual.

## Restrições

- [x] `localStorage['orcamentoPayload']` (resumo.js → resultado_orcamento.html): formato igual, só deixa de servir de chave de restauração.
- [x] Payload de `POST /api/orcamento/calcular`: sem mudança.
- [ ] Formato do `.obra`: `resultado{assinatura, linhas}` continua igual. A `assinatura` continua sendo gravada, mas não decide mais nada
  (programas antigos abrem o arquivo normalmente).
- Fora do projeto (sem `.obra` aberto), o comportamento é o de hoje: sempre calcula.

## Critérios de aceite

- [ ] Projeto aberto, Resultado calculado e gravado. Importar base nova e clicar em Montar Orçamento com o mesmo Resumo: o Resultado
      vem da base nova (log "Calculando orçamento com a base técnica...", nunca "restaurado").
- [ ] Mesmo cenário com uma edição manual no Resultado: Montar Orçamento recalcula e o log avisa que as edições foram substituídas.
- [ ] Na tela do Resultado, Projeto → Abrir um `.obra` com resultado gravado: a tabela mostra as linhas do arquivo (com as edições),
      sem chamar `/api/orcamento/calcular`.
- [ ] Na tela do Resultado, abrir um `.obra` sem resultado: tabela vazia com a mensagem do item 2.
- [ ] Recarregar a página do Resultado com projeto aberto: recalcula.
- [ ] O `.obra` gravado continua abrindo na versão anterior do programa.
- [ ] Documentação `.ai` atualizada (RULES.md Regra 9) e `STATE.md` (Regra 10). Atualizar a nota da TASK-154 ("payload igual restaura").

```
Projeto aberto, Resumo: 12600D, B4MT_RL, FLABIT, FLABIM, IT-R, RL(CABO3=A185P), ATRINT-EQ(RL), PR(TIPO=RL)
1) Montar Orçamento com a base antiga  → Resultado com 2212015 ×39 (gravado no projeto)
2) Importar base_orcamento_20261115_LUMI.csv
3) Montar Orçamento de novo
```

### Resultado esperado

```
3) Resultado recalculado: 2212025 ×39 + 2418094 ×18 (jumper 185); 2212015 não aparece.
   Abrir o mesmo .obra estando no Resultado depois disso: mostra o resultado gravado no passo 3.
```

## Arquivos potencialmente afetados

- `static/resultado_orcamento.html:1421-1480` (`montarOrcamento`): tirar a restauração. Função nova para mostrar o resultado de um projeto
  aberto (`mostrarResultadoDoProjeto`).
- `static/projeto.js:438-490` (`ativarAberto`, `abrirDoPlugin`): avisar a tela do Resultado aberta, por evento ou callback registrado como
  o `__registrarColetor`, que um projeto foi aberto (modo Abrir) e entregar o `resultado`.
- `static/projeto.js:720-728` (`carregarResultado`): passa a ser usado só por esse caminho.
- `tests/test_projeto_154.py`: só grava e lê `resultado{assinatura, linhas}` no servidor, sem mudança. A regra de restaurar está só no
  JS. Se for criado teste de JS ou de ponta a ponta, ele cobre "Montar recalcula" e "abrir .obra no Resultado restaura".

## Riscos

- O Resultado roda dentro do programa (`AbrirNaApp`, iframe). O aviso de "projeto aberto" precisa chegar à janela do Resultado e não só à
  principal (`dono()`).
- Perder edições manuais sem querer: por isso o aviso no log (item 1). Quem quer as edições abre o `.obra` na tela do Resultado.

## Plano de teste

Manual no programa com um `.obra` de teste, seguindo os critérios. Rodar `tests/test_projeto_154.py` e `tests/test_plugin_projeto_163.py`
(o formato do `.obra` não pode mudar).
