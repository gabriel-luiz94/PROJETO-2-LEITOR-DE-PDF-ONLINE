# TASK-048-06-10-2026

**`adicionar_ativo`: item da lista pode ter quantidade própria (diferente por código)**

> Pergunta do usuário, logo após a TASK-047: "a lista de códigos aceita mais de um fator?" —
> respondido que, como implementada, `qtd` era um valor único compartilhado por toda a lista.
> Usuário confirmou o pedido real: "Sim, quantidades diferentes por código pra diminuir o número de
> regras". Implementada em 2026-10-06.

## Objetivo

Permitir que um item da lista de `adicionar_ativo.ativo` (TASK-047) tenha sua PRÓPRIA quantidade,
diferente dos demais — sem precisar de uma ação `adicionar_ativo` por código.

## Contexto

A TASK-047 implementou `ativo` como lista de códigos fixos com uma única `qtd` compartilhada por
todos ("quantidade igual pra todos", decisão explícita do usuário naquela tarefa). O usuário agora
quer o oposto para o MESMO caso de uso: vários códigos na mesma ação, mas cada um com sua própria
quantidade — para não precisar de uma ação por código quando elas só diferem na quantidade.

## Situação atual (antes desta tarefa)

- `adicionar_ativo.ativo` em lista só aceitava itens string (código fixo); a quantidade de TODOS
  vinha de `qtd` no nível da ação.

## Comportamento desejado

1. Um item da lista pode ser `{"ativo": código, "qtd"?: número}` em vez de uma string simples — tem
   sua PRÓPRIA quantidade, que substitui a `qtd` compartilhada só para aquele código.
2. Itens string continuam usando a `qtd` compartilhada da ação (comportamento da TASK-047,
   inalterado) — os dois formatos podem ser MISTURADOS na mesma lista.
3. Item dict sem `qtd` usa a `qtd` compartilhada (equivalente a um item string).
4. `descrever_acao()` descreve cada item com sua quantidade (própria ou compartilhada) em português.
5. UI (`painel_ajustes.js`): o mesmo campo "códigos" (lista separada por vírgula) aceita a sintaxe
   `código:qtd` por item — um código sem `:qtd` usa a quantidade compartilhada do campo ao lado.
6. Exemplo exato do pedido do usuário: `{"acao": "adicionar_ativo", "tabela": "outros", "ativo":
   [{"ativo": "90525", "qtd": -1}, {"ativo": "90542", "qtd": -2}]}`.

## Restrições

- [x] Nenhum dos contratos listados em `RULES.md` (Regra 5) muda.
- `adicionar_ativo` continua restrito a Outros (`SO_OUTROS`).
- A quantidade própria do item é sempre um número literal (não aceita `{"soma": ...}` por item —
  só a `qtd` compartilhada da ação pode ser dinâmica, igual à TASK-045/047).
- Não combina com ativo dinâmico (TASK-046) — são modos diferentes de `ativo` (dict único vs. lista).

## Critérios de aceite

- [x] `[{"ativo": "90525", "qtd": -1}, {"ativo": "90542", "qtd": -2}]` adiciona cada código com a
  própria quantidade.
- [x] Lista mista (item com `qtd` própria + item string) funciona: o item string usa a `qtd`
  compartilhada da ação.
- [x] Item dict sem `qtd` usa a `qtd` compartilhada.
- [x] `se_ja_existe` funciona normalmente com itens de quantidade própria.
- [x] Validação rejeita item dict sem `ativo`, com campo desconhecido, `qtd` zero/não numérica.
- [x] `descrever_acao()` gera frase em português correta para lista mista.
- [x] UI: sintaxe `código:qtd` no campo "códigos" produz o JSON esperado (confirmado via
  Playwright).
- [x] Documentação `.ai` atualizada conforme `RULES.md` Regra 9.
- [x] `STATE.md` atualizado conforme `RULES.md` Regra 10.
