# TASK-019-01-10-2026

**Painel de regras de validação sai do Admin e vai para o Resumo do projeto**

## Objetivo

Mover o editor das regras de domínio (e os prompts de validação) do painel `/admin` para a página **Resumo do Projeto** (`resumo.html`), no contexto do projeto selecionado em `#select-projeto`.

## Contexto

Pedido do usuário (2026-10-01): configurar as regras de onde se valida as planilhas. Base visual das demais tasks (aba *Ajustes* entra na TASK-023).

## Situação atual

- `admin.html` hospeda hoje as regras de domínio (`#rdLista`, grupos, assistente, teste — `regras_editor.js`, TASK-017/018) e os prompts de validação (`admin.js`, `pv*`). Tudo com **classes Tailwind (CDN)** e seletor de projeto próprio.
- `resumo.html` **não usa Tailwind**: tem CSS próprio (`btn-primary`, `btn-secondary`, `modal-overlay`, variáveis `--border-default`…), já tem modais (`modal-validacao`, `modal-correcao`) e o seletor `#select-projeto`, que dispara `carregarRegras()` e `carregarRegrasLeitorResumo()`.
- Leitura de regras = qualquer autenticado; escrita = `admin`. O Resumo é usado por operadores também.
- `regras_editor.js` é global (`rd*`) e acoplado aos ids do `admin.html`.

## Comportamento desejado

1. Botão **"Regras de validação"** no cabeçalho do Resumo (junto de Validar) abre um painel grande com abas: *Regras*, *Grupos*, *Prompts da IA*, *Testar* (e, depois, *Ajustes* — TASK-023).
2. O painel segue o **projeto do `#select-projeto`** (sem seletor próprio); o padrão de todos os projetos vira uma opção dentro do painel.
3. **Operador** vê tudo em leitura (frases, selos, "por quê"); **admin** edita.
4. Editor reestilizado com o CSS do Resumo (sem Tailwind), em arquivo próprio carregado sob demanda; mesmo comportamento da TASK-017/018.
5. Seção do Admin removida (ou só um aviso "agora fica no Resumo"); nenhuma regra é perdida (mesmos dados e rotas).

## Restrições

- Sem rota nova de backend: reaproveita `/api/validacao/regras*` e `/api/validacao/prompts*`.
- Conteúdo via `textContent`; nenhuma regra de negócio no frontend (RULES Regra 4).
- Não quebrar undo/redo, modais existentes nem Montar Orçamento.
- Contratos (Regra 5): [x] Nenhum.

## Critérios de aceite

- [ ] Painel abre no Resumo, segue o projeto selecionado e mostra as regras efetivas com selos
- [ ] Admin edita/salva/reverte; operador só lê (sem botões de escrita; rotas continuam 403)
- [ ] Prompts de validação editáveis no mesmo painel
- [ ] Admin sem o painel antigo
- [ ] Verificado no navegador com o estilo do Resumo (admin e operador), sem erros de JS
- [ ] `.ai` (STATE, CHANGELOG, ARCHITECTURE) atualizados

## Arquivos potencialmente afetados

`static/resumo.html`, `static/resumo.js` ou novo `static/painel_regras.js`, `static/regras_editor.js` (desacoplar de ids/Tailwind), `static/admin.html`, `static/admin.js`, `app.py` (rota sem cache do JS novo)

## Riscos

- Editor grande numa página que já tem ~3.900 linhas de JS: arquivo próprio, carga sob demanda.
- Reestilizar sem Tailwind pode causar regressão visual: roteiro de navegador com screenshots.
