# TASK-051-07-10-2026

**Checagem obrigatória de contrato + ativo não encontrado ao clicar em Ajustar/Validar/Montar Orçamento**

> Pedido do usuário: depois da TASK-050 (quantidade decimal com vírgula na Totalizadora), perguntei
> se ele via melhorias de intuitividade/eficiência. Ele quer que erros na tabela Outros sejam
> identificados e destacados com mensagens, pra evitar erros em grandes obras. Desenho inicial
> (destaque ao vivo, linha por linha, na própria tabela) foi substituído a pedido dele: "quero que
> esse tipo de sinalização seja disparada quando clicar em ajustar, validar ou montar orçamento.
> Exiba uma mensagem e não prossiga devido às inconsistências." Confirmado por ele: bloqueia mas
> permite "continuar mesmo assim" (mesmo padrão que o Montar Orçamento já tem hoje), e roda sempre,
> automaticamente, sem precisar de nenhuma configuração. Desenho atualizado em 2026-10-08, aguardando
> autorização para implementar.

## Objetivo

Antes de **Ajustar** ou **Montar Orçamento** prosseguirem, checar automaticamente (sempre, sem
precisar ligar nada) se há erro de formato (Camada 1) ou ativo não encontrado na base técnica; se
houver, mostrar o painel de achados e só prosseguir se o usuário confirmar "continuar mesmo assim".
**Validar** já faz isso hoje, por padrão — não precisa de nenhuma mudança.

## Contexto

### O que já existe e não muda

- **Validar** (`btnValidar`, `static/resumo.js:2888-2904`) chama `executarValidacao()` e mostra
  TUDO num painel (`cicloValidacao(res, false)`) — sem bloquear nada, porque Validar não "prossegue"
  pra lugar nenhum, só informa. `MODOS_PADRAO = { det: true, dominio: true, ia: true, pularIa: true
  }` (`static/resumo.js:2410`) — Determinística vem **ligada por padrão**, e `executarValidacao`
  sempre monta e manda o payload da Totalizadora (`payloadCalculo`, linhas 2622-2630) quando
  `prefs.det` é verdadeiro, o que já dispara `validar_base` (ativo não encontrado) no backend
  (`routers/validacao.py:26-31`). **Ou seja: Validar já mostra os dois sinais pedidos, hoje, sem
  nenhuma mudança de código.**
- **Montar Orçamento** (`static/resumo.js:3475-3512`) já tem um bloqueio com "continuar mesmo
  assim" — mas é **opcional**: só roda se a preferência `validacaoAutomaticaLigada()`
  (`localStorage`, chave separada de `MODOS_PADRAO`, **desligada por padrão**) estiver ligada
  (linha 3485: `if (validacaoAutomaticaLigada() && !(await validarAntesDeMontar())) return;`).
  `validarAntesDeMontar()` (linhas 2876-2886) já faz exatamente o padrão "bloqueia mas permite
  continuar": roda `executarValidacao()`, se achar erro/aviso entra em `cicloValidacao(res,
  confirmar=true)` (que mostra o painel com opção "continuar mesmo assim"), só segue se a escolha
  for `'continuar'`.
- **Ajustar** (`btnAjustar`, `static/resumo.js:3468-3469`) **não valida nada hoje** — abre o painel
  de ajustes direto.
- `cicloValidacao(res, confirmar)` (`static/resumo.js:2849-2873`) já é genérico: mostra o painel,
  deixa aplicar ajuste/IA, revalida, e só retorna `'continuar'` quando `confirmar=true` e não sobra
  nenhum achado erro/aviso (ou o usuário confirma explicitamente). **Essa é a peça que já resolve
  "bloqueia mas permite continuar mesmo assim" — não precisa de nenhuma UI nova.**

### O que falta

1. Uma checagem **sempre ativa** (não atrás de `validacaoAutomaticaLigada()`), limitada aos dois
   sinais pedidos (Camada 1 + ativo não encontrado — **sem** regras de domínio nem IA, que
   continuam só sob demanda/opcionais), reutilizável por Ajustar e Montar Orçamento.
2. Ligar essa checagem no clique de **Ajustar** (novo) e também em **Montar Orçamento**, desta vez
   sempre, além do fluxo opcional que já existe lá (que continua funcionando, inalterado, pra quem
   já usa "Validar ao montar orçamento" pra pegar também regras de domínio/IA).

Como `executarValidacao()` já decide o que rodar a partir de `lerModos()` (preferência salva), a
forma mais simples e com menor risco é dar a ela um parâmetro opcional que força "só o básico",
ignorando a preferência salva — sem duplicar nenhuma lógica de montagem de payload, chamada de rede
ou leitura de achados.

## Situação atual

- `static/resumo.js:2606` — `async function executarValidacao()` sem parâmetros; sempre usa
  `lerModos()`.
- `static/resumo.js:3468-3469` — clique de Ajustar vai direto pra `abrirPainelAjustar()`, sem
  checagem.
- `static/resumo.js:3475-3512` — clique de Montar Orçamento só valida se
  `validacaoAutomaticaLigada()`.

## Comportamento desejado

1. `executarValidacao(somenteContrato = false)` — quando `somenteContrato` é `true`, usa
   `{ det: true, dominio: false, ia: false }` em vez de `lerModos()`. Resto da função inalterado
   (mesma montagem de payload, mesma chamada a `/api/validacao/planilhas`, mesmo formato de
   retorno) — continua rodando Camada 1 completa, incluindo `validar_base` (ativo não encontrado),
   via o mesmo `payloadCalculo` que já é montado hoje.
2. Nova função pequena, reaproveitada pelos dois botões:
   ```js
   /** Checagem mínima e SEMPRE ativa (Camada 1 + ativo não encontrado) antes de Ajustar/Montar
    * Orçamento — independente da preferência "Validar ao montar orçamento", que continua controlando
    * só a validação completa (regras de domínio/IA), nos casos em que o usuário já liga ela. */
   async function checarInconsistenciasBasicas() {
       const res = await executarValidacao(true);
       if (res.nada || res.falhou) return true;   // validação indisponível: não trava a ação
       if (!res.achados.some(a => a.severidade === 'erro' || a.severidade === 'aviso')) return true;
       const escolha = await cicloValidacao(res, true);   // mesmo painel/"continuar mesmo assim" de hoje
       return escolha === 'continuar';
   }
   ```
3. `btnAjustar`: `if (!(await checarInconsistenciasBasicas())) return;` antes de
   `abrirPainelAjustar()`.
4. `btnMontarOrcamento`: adicionar `if (!(await checarInconsistenciasBasicas())) return;` **antes**
   da linha 3485 existente — a checagem opcional mais completa (`validacaoAutomaticaLigada()`)
   continua logo depois, sem mudança, pra quem já usa essa preferência.
5. `btnValidar`: nenhuma mudança — já cobre os dois sinais por padrão.

## Restrições

Contratos de `RULES.md` (Regra 5): nenhum tocado.

- Escopo dos dois sinais obrigatórios: só Camada 1 (`C1-*`, inclusive `C1-OUT-NUM`/`C1-OUT-ORFAO`/
  `C1-QTD-ZERO`/`C1-DUP` de Outros) + ativo não encontrado (`validar_base`). Regras de domínio
  (Camada 2) e IA (Camada 3) continuam só sob demanda, via a preferência existente — não ficam
  obrigatórias.
- Não remover nem alterar o comportamento atual de `validacaoAutomaticaLigada()`/
  `validarAntesDeMontar()` — a nova checagem é ADICIONAL, roda antes, não substitui.
- "Bloqueia mas permite continuar mesmo assim" (decisão do usuário) — reaproveitar exatamente
  `cicloValidacao(res, true)`, já usado hoje pelo Montar Orçamento opcional; não criar um segundo
  padrão de bloqueio.
- Não duplicar lógica de validação em JavaScript — tudo passa pela mesma
  `/api/validacao/planilhas` já existente, só com `incluir_dominio: false` forçado.

   usuário confirmar.
2. Painel de achados abre mostrando o ativo não encontrado — o orçamento só é montado se o usuário
   confirmar "continuar mesmo assim".
