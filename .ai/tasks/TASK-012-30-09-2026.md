# TASK-012-30-09-2026

## Objetivo

Armazenar os prompts de validação como dados: semente em arquivo, tabela com histórico, edição pelo admin.

## Contexto

ADR-004, camada 3. Espelha `routers/regras_leitor.py` e a TASK-007 (seed, `ALTER TABLE` idempotente em
`database.py:init_db`, histórico com reversão, `require_role("admin")` nas escritas, leitura para qualquer autenticado).

## Situação atual

Não existe nada. `prompt_rede_eletrica.txt` é lido direto do arquivo em `ai_chat.py` e não é editável na UI.

## Comportamento desejado

- Tabela `prompts_validacao` (por `projeto_codigo`, com fallback `DEFAULT`) + `prompts_validacao_historico`; sincronização com Supabase no padrão de `regras_leitor`.
- Cabeçalho por prompt: `id`, `escopo` (`cabos`/`outros`/`ambos`), `modo` (`checar`/`corrigir`), `ordem`, `modelo`, `ativo`; corpo em texto.
- Rotas: `GET` (autenticado), `POST` salvar/reverter e `GET` histórico (admin).
- Validação de schema antes de salvar (campos obrigatórios, placeholders exigidos existentes, `saida` = JSON).
- UI admin: editor + histórico + reversão + botão "restaurar semente".
- Semente: prompt inicial criado na TASK-010, em `data/validacoes/`.

## Restrições

- Não alterar `prompt_rede_eletrica.txt` nem seu uso no chat.
- Não apagar/recriar tabelas com dados (Regra 5); `scripts/schema_supabase.sql` com migração idempotente.
- [x] Schema do Supabase

## Critérios de aceite

- [ ] Primeira execução popula a semente; segunda não duplica
- [ ] Operador não consegue salvar (403); admin salva, vê histórico e reverte
- [ ] Prompt inválido é rejeitado com mensagem
- [ ] Documentação e STATE/CHANGELOG atualizados

## Arquivos potencialmente afetados

`database.py`, `routers/validacao.py`, `scripts/schema_supabase.sql`, `config.py` (caminho da semente),
`static/admin.html`/`admin.js` (ou tela análoga à de TASK-007), `data/validacoes/*`.

## Riscos

Divergência SQLite ↔ Supabase (histórico de problemas 5–7 no STATE): não engolir erro de sincronização.

## Plano de teste

Subir app, popular semente, salvar/reverter como admin, tentar como operador, reiniciar e verificar idempotência.
