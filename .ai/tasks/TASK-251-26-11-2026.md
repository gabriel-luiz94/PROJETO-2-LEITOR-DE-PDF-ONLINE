# TASK-251 — Notação de cabos: aceitar `3xA1/0(1/0)+1/0`

**Status:** PLANEJAMENTO (26/11/2026).

## Pedido
"A task do A1/0(1/0) está aí?" — o rótulo `3xA1/0(1/0)+1/0 45 m` (3 fases A1/0, neutro 1/0, mais um condutor 1/0) deve ser aceito na tabela Cabos.

## Situação atual (`services/anotacao_cabos.py`)
- `_RE_EXTRA` (linha 31) só aceita `+<número decimal>`; `+1/0` não casa, o rótulo cai em "não reconhecido".
  Medido: `3xA1/0(1/0)+1/0` → itens vazios + erro; `3xA1/0+1/0` → idem. `3xA1/0(1/0)` (sem `+`) funciona, mas o neutro vira o ativo `1/0` (não é a família A1/0).
- `_neutro_de`: valor numérico simples (`16`) troca a seção dentro do código (`C16(16)` → `C16`); valor fracionário AWG (`1/0`, `4/0`) não passa no `fullmatch [0-9]+` e vira o texto cru `1/0`.

## Comportamento desejado
1. `+N` aceita seção AWG fracionária (`+1/0`, `+4/0`) além de decimal.
2. Neutro/extra AWG (`(1/0)`, `+1/0`) mapeia para a mesma família do cabo (`A1/0` → `A1/0`; `A4/0` → `A4/0`); seções AWG de outra família continuam como valor literal.
3. `3xA1/0(1/0)+1/0 45 m` → A1/0 ×3 fases, A1/0 neutro, A1/0 extra, comprimento 45 m. Sem regressão em `3xC16(16)+16`, `3xA35P(7,94)`, `+20kV` (tensão continua tensão).

## Restrições
- Paridade `static/anotacao_cabos.js` ↔ `services/anotacao_cabos.py` (tests/test_anotacao_cabos.py).
- Não alterar o formato antigo (`CAA2 ABC 35 m`).
- Base: A1/0 (POPPY) e A04/A4/0 já cadastrados para retensionamento/remoção/reaplicação; nada a mudar na base.

## Critérios de aceite
- Exemplos abaixo passam em Python e JS; testes existentes verdes.
- Atualizar docs `.ai` (Regra 9) e `STATE.md` (Regra 10).
